# Release Checklist

## Automated

- Run `npm ci` with the Node version in `.nvmrc`.
- Run `npm run format`, `npm run lint`, `npm run typecheck`, and `npm run test:coverage`.
- Run `npm run build` and `npm audit --omit=dev --audit-level=high`.
- Confirm the Windows CI job completes `npm run package:win:dir`.

## Windows Smoke Test

- Install the NSIS artifact from `npm run package:win`.
- Confirm startup, window restore, navigation blocking, and external-link handling.
- Add two directories and verify search, keyboard switching, and removal confirmation.
- Start each available shell, send input, resize, copy, paste, stop, and restart.
- Start a fresh Claude conversation, continue its exact name, and open the resume picker.
- Switch sessions during output and confirm replay is bounded and not restored after an app restart.
- Enable the credential monitor, complete a login, cancel a login, and verify the follow-up check.
- Exercise sounds, quiet hours, native notifications, diagnostics copy, and log-directory opening.

## GitHub Controls

- Keep the `release` GitHub environment protected with required reviewers for future trusted
  signing.
- Keep that environment restricted to matching `v*` tags.
- Keep matching `v*` tags protected so only release maintainers can create, update, or delete them.
- Never attach an unsigned executable to a GitHub Release.

## Before General Availability

- Add approved Windows and macOS application icons instead of shipping Electron's default icon.
- Archive the sanitized diagnostics report from the smoke test; never attach terminal or login output.

## Internal Candidate

1. Open **Actions → Unsigned Windows Candidate → Run workflow** and select `main`.
2. Enter the exact acknowledgement `UNSIGNED INTERNAL TEST ONLY`.
3. Download the resulting Actions artifact and confirm its name ends in `-UNSIGNED`.
4. Read the included warning, verify the checksum, and complete the Windows smoke test on a
   controlled machine.

Never distribute an unsigned candidate as a GitHub Release.

Manual workflow runs upload seven-day Actions artifacts and never create GitHub Releases.

## Source-only GitHub Prerelease

1. Run `npm version <version> --no-git-tag-version` so `package.json` and `package-lock.json` remain
   synchronized.
2. Commit and push the version change to `main`; wait for the **CI** workflow to succeed.
3. Build and smoke-test the unsigned internal candidate, retaining the successful Actions run URL.
4. Create the matching annotated tag, such as
   `git tag -a v0.1.0 -m "Claude Command Deck v0.1.0"`.
5. Push the tag with `git push origin v0.1.0`.
6. Create a source-only prerelease with generated notes and a prominent warning:

   ```bash
   gh release create v0.1.0 \
     --verify-tag \
     --title "Claude Command Deck v0.1.0" \
     --notes "Source-only prerelease. Trusted Windows signing is deferred; no installer is attached." \
     --generate-notes \
     --prerelease \
     --latest=false
   ```

7. Add the successful Actions run URL to the release notes for approved testers. State that the
   artifact expires after seven days, is unsigned, and will appear as an unknown publisher.

A published prerelease in this public repository is not access-restricted. Source archives are
generated by GitHub automatically. Do not upload the unsigned installer or its checksum as release
assets.

## Future Trusted Distribution

- Configure a publicly trusted Windows signing service before attaching installers to Releases.
- Update the workflow to sign and verify the application executable and installer, require a trusted
  timestamp, and validate the expected publisher identity.
- Use the protected `release` environment for signing credentials and approvals.
